## 类型和命名

新增 SQL 类型是建议的统一存储类型，并非官方 API 声明，也不表示已修改数据库。ID 用文本。保单和业务订单数量用 BIGINT。金额、成本及比率用 DECIMAL，广告原始指标使用 DECIMAL(20,6) 保留小数精度，避免把 API 声明为 float 的数值未经验证直接截整。来源原值超出精度时须校验，不能静默截断。比率存小数，ROI 存倍数，每千元互动数量不是百分比。

英文名优先沿用本地统一标准。`operator_id` 按现有人员 ID 规则补充。`policy_conversion_rate` 为重复歧义原行的暂定独立标识，不能视为已确认的甲方转化率。`monthly_premium` 暂不声称已年化。平台术语继续使用“统计平台”及 `stat_platform`。

## 保留的待确认项

1. 注水订单：识别及去重规则，是否已包含在后台订单提交数中。
2. 家庭保单：按订单还是按保单份数统计，与链接分项是否重叠。
3. 业务 ROI：原公式“小时”是否为服务费单价及产品、生效期配置。
4. 单均：原公式“保单÷保单量”的分子含义。既有标准建议年化保费÷保单数，但未覆盖原文。
5. 保单成本：原“总花费”是否只含广告消耗，还是含服务费的综合成本。
6. 观看成本、超 1 分钟观看率：有效观看次数是否与竞价观看数相同，以及时间阈值。
7. 互动数及每千元互动数量：次数／人数、事件范围、去重方式。
8. 表单数：普通表单、包含附加创意表单或计费时间表单的选择。
9. 订单提交率：后台订单分子及注水订单处理。
10. 保单转化率：原公式与 AD 转化率重复，不能凭字段名称改用甲方保单数或甲方 policyTransRate。
11. 月缴保费：首期实缴、年化金额或其他口径，未确认前不得乘 12。
