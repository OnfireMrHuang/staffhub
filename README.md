# 美魅网员工工作台 DEMO

React + Vite + TypeScript + Radix UI + Zustand 中文业务演示，无后端、真实平台取数或真实认证。

## 启动

```bash
npm install
npm run dev
npm test
npm run build
```

打开 Vite 显示的本地地址。当前预览使用 http://127.0.0.1:5173/。

## 登录

账号密码为主入口，企业微信、钉钉、飞书为辅助入口。

- 管理员 `admin`，公开演示密码 `StaffHub@2026`；可点击「填入管理员账号」。
- 员工使用档案中的临时编号和相同公开演示密码，登录后只查看本人。
- 正式管理员密码始终取服务端环境变量 `STAFFHUB_ADMIN_PASSWORD`；DEMO不使用真实密码。
- 退出保留业务数据，刷新需要重新登录。

## 新流程汇报

运营工作台左侧展开六项二级导航：投放产品、直播间、直播原始统计数据、时报、日报、员工月度汇总。页面不再提供对应顶部业务分区tab。

1. 投放产品：维护产品 ID/名称、平台、投放账户、状态及应用配置。应用密钥和授权码仅暂存在表单，持久化配置标记。
2. 直播间：维护直播间 ID/名称、一个平台直播账户、状态及关联产品。已有来源后账户及产品归属不可直接更改。
3. 直播原始统计数据：通过水平tab切换直播记录与直播间基础数据，去掉模型卡片和多余描述，模板、上传、表单、编辑、筛选及结构查询保持不变；投放基础数据不在入口及当前同步范围内。
4. 时报、日报：先选直播间，使用后台固定定义的表头，支持查看结构、修正基础数据、恢复自动及修订历史。DEMO内置两套样例表头，部分直播间共用、部分不同，未提供员工配置定义、公式或绑定的入口。旧整段人工修订保留追溯，不猜分为真实小时。
5. 员工月度汇总：页面仅保留导出、刷新、结构查询、筛选和表数据，行内编辑及历史继续可用；左侧仅一个统一月度表入口，取消旧直播统计明细。按“原始统计 → 有效时报 → 有效日报 → 员工月度汇总”逐层计算，粒度为员工＋直播间＋年月。固定35列，包含员工/部门/入职/协议/直播间开播资料快照、三班次时长/消耗/保费及两项排名；AD成本、保单成本暂为待定义；等待薪资天数支持人工填写非负整数；新增过去3个月的平均时薪，可维护为非负数（元/小时）。两项未填为未定义，刷新保留、归档只读。岗位贡献分别归属，兼岗去重；月度独立修订最终优先，ROI/时耗/排名自动重算，原因与历史保留。夜班02–06、早班06–08，连续同团队合并场次；新归档冻结报表、表头及绑定，旧归档缺快照时明确显示。
6. 薪酬规则仅分全局、直播间两类。全局无员工筛选条件，适用于全部符合条件的在职主播；旧当前员工规则移除范围条件、版本加一并转成全局草稿，重新发布后生效，历史任务不变。直播间先选范围再添加规则集，补贴/时薪/保费系数每类至多一条，共享范围并整组保存、发布、删除；子规则默认摘要、编辑时展开。档位支持精确数值、数值范围与关联指标范围，可按ROI排名具体名次配置时薪，编辑时保留精确类型。补贴选择计数指标×金额；保费系数规则按项目自动求和；时薪单选统计指标加成、特殊时段加成或条件保薪。条件保薪内部仍可使用员工/直播间/月度指标条件。
7. 核算按员工＋直播间＋月份合并规则：补贴累加、各保费候选总额取最大、各时薪先乘自己的时长得到金额，行月薪=max(最大保底金额,累计加成金额)+总补贴；再按员工跨直播间相加。判断日期冻结为核算月末。新明细为44列、4组表头，历史三范围48列保留原快照。独立虚构样例合计18,690元，见[手算示例](docs/examples/layered-payroll/README.md)。
8. 每月1日00:00（Asia/Shanghai）自动生成上个月的一条待核算任务，即使规则或数据尚未就绪也保留任务；发布规则只更新可用版本，不生成任务。HR手动核算时读取最新已发布规则和确认月度数据并保存快照，草稿编辑不影响发布版本。薪酬核算按月份显示一条任务，列表仅保留筛选和只读摘要；点击在当前页进入详情，支持返回。核算/重新核算二次确认后进入待复核。结果分“月度核算明细”“员工月薪汇总”两个可检索导出页签；仅明细可编辑数值、追加文本/数字/金额表头，不自动重算其他字段。修改后明确执行“应用”，按当前行总计月薪更新只读员工汇总；补充列不自动加工资。HR复核无误后手动归档，待应用修正或变化的来源/已发布规则版本阻止归档；归档冻结结果、追加列与审计并锁定该月所有来源。页面头部只读显示最近“薪酬归档月份”，无归档显示“暂无归档”。
9. 当前报表升级不清空数据、工资或归档，持久化命名空间与版本保持不变。此前产品/直播间升级曾执行一次迁移；旧多账户拆为多个直播间，原直播记录保留在主直播间、不复制时长，其他账户来源保留，需明确补录人员后才能统计。

DEMO 在登录、窗口聚焦及每分钟检查到期任务，关闭网页期间的缺失任务在下次进入时补建，重复检查不重复创建；正式系统需要后台定时调度。首次启用从当时上个月开始，已有任务与归档保留。

## 数据来源及范围

保薪条件点击“添加条件”直接追加普通字段条件，取消“新主播”“新直播间”快捷菜单。选择日期字段后，右侧可选“在过去 N 个月内”“过去 N 个月之前”“时间函数”。N默认3，可修改；按包含核算当月的月份窗口判断，例如核算2026年10月、N=3时，“内”为8月1日至10月31日，“之前”为8月1日以前。详见[过去月份条件规格](docs/superpowers/specs/2026-10-15-compensation-rule-rebuild.md#过去月份范围条件2026-10-16)。

条件保薪支持固定时薪或选择员工月度汇总表的数值字段，包含“过去3个月的平均时薪”；条件命中后读取该行原始字段值，未填时阻止核算，不按零处理。历史平均算法暂未定义，DEMO 通过月度编辑维护该值。

保薪条件已移除数值加减控件。选中日期字段后，右侧选择过去月份范围或时间函数；范围判断只填写月数，函数判断再选函数、比较符和类型匹配的对比字段。普通数值仍可对比固定值或数值字段。已有加减条件展示只读摘要，可明确重新配置；历史核算不变。详见[日期条件规格](docs/superpowers/specs/2026-10-15-compensation-rule-rebuild.md#日期字段与时间函数2026-10-16)。

- 未绑定样例报表的新直播间显示明确空状态；既有月度演示统计保留兼容来源并列出直播间，后台补齐实际表头和绑定后再接入专属报表。
- 新流程使用明确标注的2026年9月和10月模拟小时记录及报表；源表没有日期/小时、投手、场控和完整平台字段，因此不能还原为真实小时明细。
- 9月新增 mock：复用现有员工、产品和直播间关联，提供9月1—2日30条直播记录、192条直播间小时来源，汇总为12位员工、3个直播间的12行月度数据。沿用时报→日报→月度汇总计算与排名，刷新可重建；不代表整月真实绩效。旧浏览器状态仅在9月无来源、统计、修订或工资/归档记录时一次补入，不覆盖已有内容。AD成本、保单成本及未提供的人工指标继续显示未定义。
- 员工姓名沿用真实绩效资料，临时编号、任职、部门及平台绑定为DEMO配置。
- [各直播间薪资标准](https://meimeiwangluo.feishu.cn/docx/WrdvdEYbaosZOExIB4Fcs1w9nMd)：原17类标准及6个明确基础规则保留，原条款只读保留，未实际配置的条款不自动计入。
- [直播间主播绩效统计](https://meimeiwangluo.feishu.cn/wiki/JPpdwtnehi6dlTkNd83cJvyjnv0)：原190条记录、34项目、150员工姓名及2026年9月实际数据保留在来源文件和旧浏览器命名空间，不重新解释为新流程真实明细。
- 新规则初始提供明确标注的全局与直播间样例草稿，不自动发布；旧规则、任务和归档保留原依据，新旧待核算任务不可混用。夜班、早班保费使用实际对应班次成交贡献，正常保费=总保费−夜班−早班。新系数公式仅累计所选项，默认正常＋早班公式不计夜班；历史缺失值不按时长猜测。旧员工范围迁移为全局草稿时仅取消范围条件，计算配置保留；其他旧模板仅在编辑并保存后升级，冻结任务不改写。当前为本地演示，未实际发放。
- 状态仍使用 `meimei-staffhub-department-rules-v1`，本轮升级持久化版本为1，旧 `meimei-staffhub-live-v1`、`meimei-staffhub-demo-real-v3` 不删除。上传文件不发送外部服务，当前任务不提交、推送或发布。
