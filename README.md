# 美魅网员工工作台 DEMO

React + Vite + TypeScript + Radix UI + Zustand 中文业务演示，无后端、真实平台取数或真实认证。

## 启动

```bash
npm install
npm run dev
npm test
npm run build
```

打开显示的本地地址。当前预览使用 http://127.0.0.1:5174/。

## 登录

账号密码为主入口，企业微信、钉钉、飞书为辅助入口。

- 管理员 `admin`，公开演示密码 `StaffHub@2026`；可点击「填入管理员账号」。
- 员工使用档案中的临时编号和相同公开演示密码，登录后只查看本人。
- 正式管理员密码始终取服务端环境变量 `STAFFHUB_ADMIN_PASSWORD`；DEMO不使用真实密码。
- 退出保留业务数据，刷新需要重新登录。

## 新流程汇报

1. 投放产品：维护产品 ID/名称、平台、投放账户、状态及应用配置。应用密钥和授权码仅暂存在表单，持久化配置标记。
2. 直播间：维护直播间 ID/名称、一个平台直播账户、状态及关联产品。已有来源后账户及产品归属不可直接更改。
3. 数据录入：仅保留直播记录与直播间基础数据，两表均展示产品 ID/名称及直播间 ID/名称，表结构只读。模板按直播间生成四个关联字段，上传统一校验产品与直播间一致性。
4. 直播间来源按产品＋直播间＋小时模拟落表，重复同步不累加；统计仅采用直播间基础数据，旧投放数据仅保留历史，不开放录入/查询/导出，当前同步不再采集。
5. 运营数据集：明细及月度汇总固定结构，月度粒度为员工＋直播间＋年月，保留产品维度。三岗分别汇总、兼岗不重复；夜班02–06、早班06–08，同直播间同月ROI排名。
6. 薪酬规则按部门分类，绑定一个或多个直播间；弹窗定义常规/时长指标、精确/开放范围/关联档位，表达式逐项相加。先保存草稿，再发布生成任务，投放与素材部门新增显示待开发。
7. 核算统一处理全部当月有效任务，各项时薪乘各自绑定时长再相加；成功后归档。待核算任务可撤回、修改并重新发布，原历史保留。
8. 页面头部只读显示最近“薪酬归档月份”，无归档显示“暂无归档”。业务月份选择分别位于运营工作台和薪酬核算页面，不能手动修改归档状态。
9. 本轮模型升级只执行一次迁移，清空原核算任务、工资批次/结果及归档；保留员工、运营来源及规则。旧多账户拆为多个直播间，原直播记录保留在主直播间、不复制时长，其他账户来源保留，需明确补录人员后才能统计。

## 数据来源及范围

- 新流程使用明确标注的2026年10月模拟小时记录及报表；源表没有日期/小时、投手、场控和完整平台字段，因此不能还原为真实小时明细。
- 员工姓名沿用真实绩效资料，临时编号、任职、部门及平台绑定为DEMO配置。
- [各直播间薪资标准](https://meimeiwangluo.feishu.cn/docx/WrdvdEYbaosZOExIB4Fcs1w9nMd)：原17类标准及6个明确基础规则保留，班次、排名、保薪等特殊奖励未自动计入。
- [直播间主播绩效统计](https://meimeiwangluo.feishu.cn/wiki/JPpdwtnehi6dlTkNd83cJvyjnv0)：原190条记录、34项目、150员工姓名及2026年9月实际数据保留在来源文件和旧浏览器命名空间，不重新解释为新流程真实明细。
- 新规则薪资为各指标项贡献之和，不叠加旧方案固定薪资；低ROI来源保底条件明确保留，其他来源条款只有实际配置后参与。当前为本地演示，未实际发放。
- 状态仍使用 `meimei-staffhub-department-rules-v1`，本轮升级持久化版本为1，旧 `meimei-staffhub-live-v1`、`meimei-staffhub-demo-real-v3` 不删除。上传文件不发送外部服务，当前任务不提交、推送或发布。
