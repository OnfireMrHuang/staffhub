# 美魅网员工工作台 DEMO

React + Vite + TypeScript + Radix UI + Zustand 的中文交互演示。所有操作保存于浏览器本地，不连接后端、真实 SSO 或投放平台。

## 启动

```bash
npm install
npm run dev
```

打开终端显示的本地地址。若默认端口被占用，Vite 自动使用下一个端口。

```bash
npm test
npm run build
```

## 登录演示

账号密码为主入口，企业微信、钉钉、飞书为辅助入口。打开页面先登录：

- 管理员：`admin`；员工：员工档案中的临时编号（例如 `MM0019`）。
- 公开演示密码均为 `StaffHub@2026`，可点击「填入管理员账号」快速填写。
- 员工无需绑定平台身份即可使用账号密码；辅助 SSO 仅模拟已绑定身份匹配。
- 右上角菜单可退出登录或切换账号；退出保留业务数据，刷新后需要重新登录。

前端仅演示登录交互。正式管理员密码始终由服务端 `STAFFHUB_ADMIN_PASSWORD` 环境变量验证；员工独立密码由后端安全存储，本 DEMO 不使用真实密码或实现正式认证。

## 汇报操作

左下角点击「开始导览」，按员工管理、投放项目、数据录入、运营数据集、薪酬规则、薪酬核算六步查看业务链路。

1. 投放项目的「项目配置」支持巨量引擎 `app_id`、`secret`。使用虚构值演示；只保存应用 ID 和密钥配置状态，密钥不持久化、不回显，正式接口还需账户授权。
2. 数据录入支持固定 Excel 模板、上传、表单新增与更正、条件预览和确认。广告、直播仅预览与模拟同步。
3. 数据集点击「清洗并发布」，生成员工 + 项目 + 月份粒度的统计快照，包含部门。
4. 薪酬规则可编辑时薪枚举、项目集与目标部门，查看真实来源条款、试算并发布版本。
5. 薪酬核算运行任务、展开员工明细、锁定、发布及导出表格。发布后切换「员工端」查看本人薪资条。
6. 右上角身份菜单可重置演示，以恢复初始来源数据和配置。

## 实际资料及演示约定

- [各直播间薪资标准](https://meimeiwangluo.feishu.cn/docx/WrdvdEYbaosZOExIB4Fcs1w9nMd)：读取日期 2026-10-12。登记17类标准，接入6个明确的 ROI + 时耗基础规则。
- [直播间主播绩效统计](https://meimeiwangluo.feishu.cn/wiki/JPpdwtnehi6dlTkNd83cJvyjnv0)：导出190条来源记录、34个项目、150个独立员工姓名。总计行用于核对，不重复计入员工统计。
- 用户已确认按2026年9月展示，生成临时员工编号。原表未提供正式员工ID及任职信息，因此姓名之外的员工档案、部门和平台绑定为演示配置；同名正式归属需HR核对。
- 4条多人联合记录未分配到个人；3条「留资数 / 留资成本」口径记录不能当作年化保费，均保留在来源明细中。183条有效员工项目记录参与工作统计。
- 数据集取「实际时长」，重算时耗和ROI。原表时耗主要按「在线表时长」计算，其已舍入展示值保留在原始资料，规则匹配使用重算的未舍入值。
- 源表年化保费原数值保留，不重复施加早班系数。档位在DEMO中按阈值构造区间，端点及附加档位低于起点的处理在规则页说明。
- E生保与E生保2号在DEMO共用E生保标准，形成多项目聚合示例，此项目归类仍须业务确认。
- 用户已确认夜班、早班、排名、成本、保薪、兼职、带教等奖励先列为待配置，不参与本次自动核算。
- 默认目标只选择所有工作项目均已有基础规则的39位员工，其他员工保留完整工作数据，明确排除试算，避免只算部分项目形成不完整月薪。
- 来源未提供主播固定薪资金额，DEMO暂设0；可在月薪目标编辑演示值。运营底薪2500不能套用到主播。
- 工资结果属于基础规则试算，不是正式完整工资。已锁定/发布的月份保留快照，来源更正不会重写历史工资。

源Excel副本位于被Git忽略的 `artifacts/sources/`；应用使用的归一化来源记录保存在 `src/data/performance.json`。不会修改飞书原资料或向外部服务发布。
