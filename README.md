# 美魅网员工工作台 DEMO

React + Vite + TypeScript + Radix UI + Zustand 中文业务演示，无后端、真实平台取数或真实认证。

## 启动

```bash
npm install
npm run dev
npm test
npm run build
```

打开显示的本地地址。当前预览使用 http://127.0.0.1:5174/。

## 登录

账号密码为主入口，企业微信、钉钉、飞书为辅助入口。

- 管理员 `admin`，公开演示密码 `StaffHub@2026`；可点击「填入管理员账号」。
- 员工使用档案中的临时编号和相同公开演示密码，登录后只查看本人。
- 正式管理员密码始终取服务端环境变量 `STAFFHUB_ADMIN_PASSWORD`；DEMO不使用真实密码。
- 退出保留业务数据，刷新需要重新登录。

## 新流程汇报

1. 投放项目：项目编码/名称、巨量引擎或磁力引擎或腾讯ADQ、投放账户、多直播账户、应用ID/密钥/授权码。项目不关联员工；密钥和授权码只暂存在输入表单，不持久化。已有来源的项目平台与账户绑定只读，新账户以新项目承接。
2. 数据录入：仅直播记录表、投放基础数据、直播间基础数据；三表均支持「查看表结构」，字段及说明只读。直播记录可下载多项目+日期+整体时段+整小时分片模板，手填主播/投手/场控，上传、表单录入、预览、过滤及编辑。
3. 员工姓名全局唯一，上传按唯一姓名解析ID；项目编码名称须一致，三类人员均填写，起止必须整小时对齐。同项目记录不能重叠。
4. 两类平台表逐小时模拟落表，所有固定字段只读预览；模拟同步会补齐当前直播记录日期的全天小时样例，重复同步不累加；实际统计仅采用直播间基础数据，投放基础数据供独立查看，不叠加两类消耗。
5. 运营数据集：固定员工直播明细和固定员工直播月度汇总，两表均可查询表结构，字段标注维度、时长指标或常规指标，元数据只读，无表字段配置。三岗位分别汇总，同人兼岗不重复；岗位业务贡献不能相加为项目总额。
6. 夜班02:00–06:00、早班06:00–08:00；连续同项目同人员组合合并场次。保费=营销成交金额，ROI同项目同月竞争排名（1、1、3）。月度“主播”列展示参与记录中的主播名单。
7. 薪酬规则：真实来源的ROI+时耗基础档位绑定固定月度统计，显式部门与员工名单；默认只把示例主播纳入主播方案，投手/场控已有统计，工资策略另行配置。
8. 月度核算成功即保存快照并归档月份。所有上传、表单、编辑、同步及统计重建拒绝已归档月份；编辑也检查原日期，不能移到新月份绕过。随后确认锁定、发布，员工可查看本人薪资条。
9. 右上角菜单可重置新版模拟样例，清除新版试算和归档状态；不删除旧版本地数据或修改飞书文档。

## 数据来源及范围

- 新流程使用明确标注的2026年10月模拟小时记录及报表；源表没有日期/小时、投手、场控和完整平台字段，因此不能还原为真实小时明细。
- 员工姓名沿用真实绩效资料，临时编号、任职、部门及平台绑定为DEMO配置。
- [各直播间薪资标准](https://meimeiwangluo.feishu.cn/docx/WrdvdEYbaosZOExIB4Fcs1w9nMd)：原17类标准及6个明确基础规则保留，班次、排名、保薪等特殊奖励未自动计入。
- [直播间主播绩效统计](https://meimeiwangluo.feishu.cn/wiki/JPpdwtnehi6dlTkNd83cJvyjnv0)：原190条记录、34项目、150员工姓名及2026年9月实际数据保留在来源文件和旧浏览器命名空间，不重新解释为新流程真实明细。
- 正式固定薪资金额缺来源，DEMO仍暂设0，可在规则中修改演示值；当前工资为基础规则试算，未实际发放。
- 新状态使用 `meimei-staffhub-live-v1`，旧 `meimei-staffhub-demo-real-v3` 不删除。上传文件不发送外部服务，当前任务不提交、推送或发布。
