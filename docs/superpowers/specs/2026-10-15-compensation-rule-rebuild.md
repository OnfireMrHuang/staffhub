# 薪酬规则重构规格

日期：2026-10-15；规则定义与删除功能更新于2026-10-16。本文件记录三分类、三类型规则的配置规格。

## 员工与直播间字段

员工增加`non_compete_signed BOOLEAN NOT NULL DEFAULT FALSE`，前端`nonCompeteSigned`。新增及历史缺省员工补False，保存只接受布尔值；档案与本人资料显示签约状态。旧归档人员快照不回写。

直播间增加可维护的`opened_on DATE NULL`开播日期，用于开播月龄条件；不把最早采集日期猜作真实开播日。规则引用缺失的开播/入职日期时提示补齐，不自动当作命中或不命中。

## 范围分类

| 分类 | 定义方式 |
| --- | --- |
| 全局规则 | 直接定义，应用于有当期月度工作数据的在职员工 |
| 直播间规则 | 下拉多选未被其他当前规则占用的直播间，再定义规则 |
| 员工规则 | 用员工字段的逻辑条件定义人员，例如协议=True、岗位=主播、入职最近3个月，再定义规则 |

分类由新增入口确定，新增、编辑和详情中的分类字段均只读，保存接口拒绝已有规则切换分类。直播间规则先配置适用直播间，员工规则先配置员工逻辑表达式，全局规则直接进入定义；三类共用同一规则定义组件，包含规则名称、计算类型及对应配置（保费系数、时薪的保薪/加成、补贴）。

直播间下拉框支持多选，其他当前直播间规则（包括草稿和已发布）已选的直播间显示占用规则名称并禁选，计算类型不同也不能重复绑定；当前规则已选直播间可保留或取消。全局规则和员工条件不占用直播间。保存与发布均校验当前绑定唯一性，旧重复绑定保留数据供调整，不直接发布；编辑移除直播间后释放当前占用。旧已归档快照不占用当前绑定；同月其他规则的待核算快照仍包含该直播间时，需先撤回相关任务才能发布新规则，避免旧快照与新规则重复计薪。

范围分类与计算类型独立。每条员工＋直播间＋月份数据行先匹配全部已发布有效规则，再合并成一套结果计算一次；不把每条时薪规则独立算薪后重复相加。

## 条件与日期

使用类型受控的字段、运算符、值与嵌套AND/OR组，不执行自由JavaScript。员工范围仅引用employee字段，避免用处理后的月度指标反过来循环决定规则适用人员；条件保薪可引用员工、直播间和月度指标。新保费系数规则直接配置系数项，不再配置早班场次触发条件。

以核算月份最后一天为判断基准并冻结。最近N个月采用日历月回溯，月末越界夹至目标月末，含下限与基准日，不包含未来日期。布尔和文本只支持等于/不等于；数值支持比较；日期支持日期比较与最近N个月。空组、未知字段、错误值类型和循环/过深结构拒绝。必要输入缺失不猜测。

## 数据输入拆分

| 字段 | 口径 |
| --- | --- |
| 总保费 | 有效运营统计中的总成交金额 |
| 早班保费 | [06:00,08:00)实际小时成交贡献合计 |
| 正常保费 | 总保费−夜班保费−早班保费（2026-10-16确认） |
| 正常直播时长 | 总直播时长−夜班直播时长−早班直播时长 |
| 早班/夜班场次 | 沿用连续同团队合并场次规则 |

月度含nightPremium、earlyPremium、regularPremium、regularHours、regularSpend及spendRank。夜班和早班保费为可核验修正的基础值，二者之和不得超过总保费；正常保费、正常消耗和正常时长自动计算，不接受人工填写。时报/日报来源、人工纠正与下游分配延续既有审计；缺少夜班或早班金额的旧历史仍为未知，不按时长比例猜作实际平台金额。

## 三阶段规则及合并

### 1 补贴

选择员工月度汇总中的计数指标，当前可选夜班场次、早班场次，设置每次补贴金额。每条命中规则金额=所选计数指标×补贴金额，同一行所有补贴金额累加。计数必须为非负整数，金额必须为有限非负数。补贴不改变保费、消耗和时长，也不再参与后续系数相乘。

### 2 保费系数

名称统一为“保费系数规则”。规则包含一个或多个可新增、删除的系数项，每项配置名称、保费字段和保费系数。字段可选总保费、夜班保费、早班保费、正常保费，系数为有限非负数，允许0和小于1的折减。只读公式随项目列表自动生成“系数项1 + 系数项2 + …”，单项金额=原始保费字段×该项系数。

多个范围的保费系数规则同时命中时，每条规则独立读取同一份原始月度数据，先求本规则所有系数项总额，再取最高总额作为有效总保费；不逐字段拼出新规则，不叠加规则结果，也不与原始总保费再次取最大。未命中任何保费系数规则才沿用原始总保费。未选字段不自动补入；默认“正常保费×1 + 早班保费×1.2”仍排除夜班，只有显式加入夜班或总保费项才计入对应金额。正常保费始终=总保费−夜班保费−早班保费。

例如原始正常保费700、早班200、夜班100，规则A=正常×1+早班×2=1100，规则B=总保费×1.05=1050，采用A的1100，而不是选择数值最大的单个系数后重新套用其他字段。零系数结果有效。

计算使用工作副本，不回写运营数据；有效总保费、有效ROI及同直播间同月ROI排名随选中结果更新，后续时薪使用有效值。原始组成字段的取值依据保留在计算轨迹中。保费不直接作为工资金额相加。轨迹包含各候选规则、逐项原值、系数、金额、总额及是否采用，便于复核；结算层的有效字段与范围金额口径见[分层核算规格](2026-10-16-layered-payroll-settlement.md)。

### 3 时薪

每条时薪规则先选择总/夜班/早班/正常直播时长之一，再单选一种时薪计算类型；同一条规则不混合三种类型，切换类型清除当前未保存的类型配置。

- 统计指标加成：以列表管理指标，支持新增、编辑、删除；配置弹窗包含名称、统计指标和时薪档位，复用精确值、开放上下界、关联指标档位。只读计算公式按列表顺序显示全部指标名称之和，增删、改名时自动更新，不再手动选择公式项目。

  档位列表底部提供“新增档位”，无须返回顶部。已有档位默认以一行展示序号、匹配条件、时薪和编辑/删除操作；精确值、开闭区间及关联指标均在摘要中明确表达。新增或编辑时仅展开当前档位，点击“完成”通过完整档位校验后收起。切换编辑时仅检查当前档位的字段完整性，允许调整相邻区间时暂时重叠；完成、新增下一档位和保存时检查区间重叠。删除前序档位后仍保持正在编辑的同一条数据。新建统计指标或更换统计指标时，初始档位自动展开。只读详情展示相同摘要，不提供编辑操作。
- 特殊时段加成：直接设置加成金额（元/小时），按本规则选择的时长计薪，不显示指标列表或档位。
- 条件保薪：直接配置保薪条件与保薪值（元/小时），例如开播未满3个月或新人主播，不显示指标列表或档位。

单条统计指标规则公式必须包含全部指标且顺序一致，特殊时段与条件保薪分别只有一份配置。合并所有规则时按时长字段分组：组保薪取所有触发值的最大值，组加成取全部有效加成之和，最终组时薪=max(组保薪,组加成)。组金额=组时薪×该字段时长，各组金额相加；不同直播间分别处理，不跨直播间平均ROI。

例如保薪60、加成80，采用80元/小时；总时长组与夜班时长组分别计算后相加。总时长组覆盖所有时段，另加夜班组属于明确叠加，不能解释为互斥时段。

### 月薪

月薪=各数据行补贴金额＋各时长组金额。例：总保费1000、夜班保费0、早班保费200，两条公式“正常×1＋早班×1.2”和“正常×1＋早班×1.5”分别得到1040和1100，采用1100；夜班2场、两条每场补贴20和10则补贴60；总时长10小时、保薪60与加成80取80得800；另有夜班2小时×10元得20，合计880。

## 校验与任务

范围及日期、基础数据有限非负、整数字段、总量关系、重复员工直播间月份、规则及项目ID、公式引用、档位缺失/多命中、无效分母及金额溢出均校验。失败不产生部分工资。

保存生成草稿版本，发布冻结规则、月份、月末基准、员工名单、数据行键与数据集版本。发布后修改来源/统计版本或适用行范围，核算拒绝，撤回待任务并核对后重新发布。整月全部新任务调用合并引擎一次，成功后保存工资和归档。

新旧规则任务分离，旧部门规则及其工资保留原引擎与快照。新旧有效待核算任务混合时拒绝，先撤回旧任务再使用新版，不能把两套模型的结果盲目相加。

### 删除规则

各分类规则卡片提供删除入口，确认弹窗显示规则名称和待撤回任务数量。确认后以`deletedAt`标记删除，从当前列表移除并释放直播间占用，同一事务撤回该规则全部月份的待核算任务。已核算任务、历史工资、归档及其规则快照保持原样。已删除规则不能继续保存或发布，防止旧编辑窗口恢复规则。若相关待核算任务属于归档月份，拒绝整个删除操作，避免部分删除或篡改归档。

## 持久化与审计

DEMO新增compensationRules/compensationTasks及一次初始化标记，沿用现有存储命名空间和版本1；不清空员工、来源、工资或归档。初始化仅提供明确标识的草稿样例，不自动发布。

正式MySQL以compensation_rule_rooms保存当前直播间绑定（room_id唯一、rule_id关联当前规则），保存时事务校验占用并更新绑定；版本和任务中的直播间范围独立冻结。规则分类创建后不可更改。拟增加compensation_rules及rule_versions（范围、条件AST、计算类型、definition_version、模板配置、版本及deleted_at）、compensation_tasks（日期基准、冻结规则、员工名单、行键及统计版本）、payroll_row_calculations（命中规则、候选保费公式与采用结果、有效ROI/排名、保薪/加成、时长、补贴及结果）。删除规则、释放当前绑定、撤回待任务必须原子提交；冻结版本不被删除。模板JSON记录补贴计数字段、系数项数组、时薪子类型及指标项。JSON条件必须通过服务端相同类型校验，不能作为SQL/脚本执行。

工资快照冻结上述计算依据、当期员工协议/入职值、直播间开播日期和规则版本。以后修改员工、直播间或草稿均不改历史工资。六条原始来源规则只读保留，未作不等价自动转换。

新建规则使用`definitionVersion=2`。旧模板数据和任务不自动改写；查看显示原配置，编辑时生成新模板草稿并提示差异：旧保费规则转换为正常与早班系数项，原系数触发条件不带入；旧时薪公式按第一个有效项目确定类型，仅保留相同类型（特殊时段/保薪保留一项），旧加成触发条件不带入。取消不保存这些变化，保存后才生成新草稿版本。旧任务继续引用原快照。

## 页面

规则页从全局/直播间/员工三个水平分类开始，当前分类内先显示唯一的“新增薪酬规则”按钮，再展示规则列表；新增规则默认归属当前分类。移除页面标题说明、核算月份选择、规则数量概览、计算顺序提示及“来源与历史规则”入口。卡片保留名称、类型、版本、状态、计算配置、适用范围和操作。弹窗顶部只读展示分类，先维护该分类的直播间或员工范围，再使用统一规则定义组件维护名称、计算类型、模板项目、条件和公式，支持查看、保存与发布。核算月份仅在发布弹窗中选择，旧来源规则及历史计算快照仍保留。员工条件可嵌套AND/OR，日期、布尔、数字使用对应控件。

工资任务展示分类、类型和冻结范围；工资详情展示每条数据行的规则合并、候选保费公式及最高总额、保薪/加成比较、时长组及所选计数补贴。旧历史工资继续使用原详情。
