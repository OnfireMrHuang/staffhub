# 薪酬规则重构规格

日期：2026-10-15；更新于2026-10-17。本文件记录全局、直播间两分类及补贴、保费系数、时薪三类型规则的配置规格。核算复核与手动归档以[月度任务与复核规格](2026-10-16-payroll-review-workflow.md)为准。

## 员工与直播间字段

员工增加`non_compete_signed BOOLEAN NOT NULL DEFAULT FALSE`，前端`nonCompeteSigned`。新增及历史缺省员工补False，保存只接受布尔值；档案与本人资料显示签约状态。旧归档人员快照不回写。

直播间增加可维护的`opened_on DATE NULL`开播日期，用于开播月龄条件；不把最早采集日期猜作真实开播日。规则引用缺失的开播/入职日期时提示补齐，不自动当作命中或不命中。

## 范围分类

| 分类 | 定义方式 |
| --- | --- |
| 全局规则 | 直接定义，无员工筛选条件，适用于全部符合结算资格的在职主播月度行 |
| 直播间规则 | 下拉多选未被其他当前规则集占用的直播间，再添加规则集；补贴、时薪、保费系数每类至多一条 |

分类由新增入口确定，新增、编辑和详情中的分类字段均只读，保存接口拒绝已有规则切换分类。全局规则直接进入定义，直播间规则先配置适用直播间；两类共用同一规则定义组件，依次选择计算类型、定义规则名称及对应配置（保费系数、时薪的保薪/加成、补贴）。全局分类维护单条规则，直播间分类维护规则集。

取消独立员工规则分类及员工范围条件。旧当前员工规则保留名称和计算配置，迁移为全局草稿、版本递增并移除 `employeeCondition`；适用范围扩大后必须重新发布。历史已发布任务和归档快照保留原分类与条件，不改写历史金额。条件保薪内部的员工条件仍可配置，不因范围条件取消而删除。

直播间下拉框支持多选，一个直播间只能归属一个未删除规则集，草稿和已发布均占用。集内补贴、时薪、保费系数共享相同直播间范围，每类至多一条，可只配置其中一类或两类。其他规则集已选的直播间显示占用并禁选；编辑排除整个当前规则集。全局规则不占用直播间。保存、发布校验当前绑定唯一性；历史归档快照不占用当前绑定。其他规则集的当前发布版本仍包含该直播间时，须先发布更新或删除旧规则集再发布新绑定；仅保存草稿不释放已发布范围。

规则集编辑先选直播间，再选未使用的计算类型添加规则，随后填写名称与配置。子规则类型在本次配置中只读，需要更换类型时删除后重新添加。未编辑的子规则仅展示类型、名称和计算摘要；新增或编辑时仅展开一条，完成后收起。可删除集内子规则，保存时至少保留一条。规则集统一保存、发布、删除；不提供单独发布子规则的入口。已有直播间单条规则显示为单条规则集，首次保存才写入分组标识，不改历史任务。

范围分类与计算类型独立。每条员工＋直播间＋月份数据行先匹配全部已发布有效规则，再合并成一套结果计算一次；不把每条时薪规则独立算薪后重复相加。

## 条件与日期

使用类型受控的字段、运算符、值与嵌套AND/OR组，不执行自由JavaScript。规则范围不再配置员工条件；条件保薪仍可引用员工、直播间和月度指标。新保费系数规则直接配置系数项，不再配置早班场次触发条件。

以核算月份最后一天为判断基准并冻结。布尔和文本只支持等于/不等于；数值支持固定数值或数值字段比较，配置界面不再提供加减运算。空组、未知字段、错误值类型和循环/过深结构拒绝。必要输入缺失不猜测。

### 日期字段与时间函数（2026-10-16）

保薪条件选中日期字段后，右侧“日期判断”提供三种方式：

1. **在过去 N 个月内**：同一行填写月数，默认3，可修改为有效正整数，按包含核算月的完整月份窗口判断，不显示比较符与对比字段。
2. **过去 N 个月之前**：同一行填写月数，默认3，判断日期是否早于同一窗口的起始日；起始日当天不属于“之前”。
3. **时间函数**：下一行显示时间函数、比较符、对比字段。函数可选“不处理（日期）”“提取年份”“提取月份”；切入此方式默认提取月份并对比月度汇总月份。

“内”和“之前”互相切换时保留月数；切换为时间函数或切换字段时清理不适用的配置。新增日期条件默认“在过去 N 个月内”、N=3，从时间函数切回月份判断时也默认3。“添加条件”直接新增普通字段条件，不再展示快捷菜单或“新主播”“新直播间”入口。不开放自由函数或脚本，也不再提供数值加减控件。

| 左侧处理 | 结果类型 | 右侧可选范围 | 示例 |
|---|---|---|---|
| 不处理 | 日期 | 日期字段 | 入职日期 ≤ 直播间开播日期；入职日期 ≤ 核算基准日（月末） |
| 提取年份 | 数值 | 数值型字段 | 提取年份（入职日期）= 汇总年份 |
| 提取月份 | 数值 | 数值型字段 | 提取月份（入职日期）= 汇总月份 |

- 日期字段包含入职日期、直播间开播日期和核算基准日（月末）；基准日随任务冻结，不使用浏览器当前日期。
- 新增数值条件字段“汇总年份”“汇总月份”。年份读取员工月度汇总的年份，月份将该行的 `YYYY-MM` 期间映射为 1–12 的整数，不把整段期间字符串作为数字比较。
- 右侧列表由左侧处理后的类型过滤；切换字段或时间函数时清理不再合法的比较目标。日期字段不处理时禁止选择数值字段；提取年份或月份后禁止选择日期字段。比较符支持等于、不等于、大于、大于等于、小于、小于等于。
- 新建日期条件默认采用在过去3个月内（含核算月）；切换“不处理（日期）”后采用日期字段比较，不再显示固定日期输入框。数值字段可选择固定数值或同类型字段作为比较对象；文本、布尔字段仍使用固定值。
- 判断“入职当月”可选择“入职日期，在过去1个月内”；高级配置仍可使用年份相等与月份相等的 AND。仅比较月份表示跨年份的同一月份，这是使用者明确选择的条件，不隐式增加年份限制。
- 日期以 `YYYY-MM-DD` 的日历日期处理，提取年、月不会受浏览器时区影响。非法日历日期、缺失日期、非法数值或未知函数必须报错，不允许自动转换或默认为不命中。AND/OR 所有分支都校验必要输入。
- 历史固定日期与“最近 N 个月内”条件保留原定义及结果；查看和原样保存不改写，编辑器明确标为已有条件。选择新的时间函数或字段比较后按本节类型规则配置。旧“最近 N 个月内”继续采用含下限、含基准日的日历月回溯，月末夹至目标月末且排除未来日期。

条件 AST 使用 `field` 表示左字段、可选 `transform: "year" | "month"` 表示时间函数、`compareField` 表示右字段；字段比较不同时保存 `value`。例如当月入职条件为：

```json
{"kind":"group","operator":"and","children":[
  {"kind":"condition","field":"employee.joined","transform":"year","operator":"eq","compareField":"monthly.year"},
  {"kind":"condition","field":"employee.joined","transform":"month","operator":"eq","compareField":"monthly.month"}
]}
```

MySQL 的规则版本 JSON 保存完整 AST；发布冻结 AST 定义，HR 核算时再冻结核算基准日及来源版本，核算证据记录左右字段原值及时间函数结果。服务端执行相同类型白名单校验。归档后仍读取冻结结果，不因员工资料或当前规则改变而重新解释历史条件。

### 过去月份范围条件（2026-10-16）

“添加条件”直接追加一条普通字段条件，先选择字段，再配置判断方式；没有下拉菜单或业务快捷项。可选择员工入职日期、直播间开播日期或核算基准日，选择日期字段后默认“在过去 N 个月内”、N=3。

月份沿用已确认的口径，包含核算当月。窗口以任务核算月份为准，起点为核算月向前 `N−1` 个月的第一天，终点为核算月最后一天，不使用浏览器当天。两种判断的边界如下：

| 日期判断 | 命中范围 | 2026年10月、N=3示例 |
|---|---|---|
| 在过去 N 个月内 | 起始日 ≤ 日期 ≤ 核算月末 | 2026-08-01至2026-10-31，首尾均包含 |
| 过去 N 个月之前 | 日期 < 起始日 | 2026-08-01以前，不含该日 |

2026年1月、N=3时，起点为2025-11-01；N=1时，“内”为核算当月，“之前”为核算月首日以前。支持修改N、跨年与闰年；未来日期不会命中任一种判断。两种模式切换时保留N。

多条件继续支持AND/OR与嵌套组合。月数不得为空、0、负数、小数或非有限值；超出系统有效日期范围时拒绝核算。源日期缺失或非法时明确报错，不默认为不命中。

AST 保留 `withinCalendarMonths` 表示“内”，新增 `beforeCalendarMonths` 表示“之前”；`value` 保存月数，仅适用于原始日期字段，禁止同时保存时间函数、加减或对比字段。例如“入职早于过去3个月窗口，且直播间在该窗口内开播”：

```json
{"kind":"group","operator":"and","children":[
  {"kind":"condition","field":"employee.joined","operator":"beforeCalendarMonths","value":3},
  {"kind":"condition","field":"room.openedOn","operator":"withinCalendarMonths","value":3}
]}
```

规则版本JSON与核算快照保存完整定义；证据记录源日期、实际窗口起始日、核算月末及命中结果，展示“入职日期在过去3个月之前”等字段条件表达，不套用“新主播”“新直播间”标签。已有 `withinCalendarMonths` 仅更新展示文案，定义和计算不变；更早的 `withinMonths` 继续保留原按日回溯语义，不改写历史任务和归档。

### 历史数值运算兼容（2026-10-16）

当前保薪条件不再提供加减常数的新增或编辑入口。普通数值字段仍支持固定数值或数值字段比较；日期使用上述范围或时间函数交互。

- 已保存的 `adjustment` / `compareAdjustment` 不静默移除，也不隐藏后继续以普通可编辑条件展示：编辑器显示完整的只读表达式摘要。
- 编辑时可点击“重新配置”，以同一字段创建不含运算的新条件；日期字段重置为在过去3个月内，数值字段重置为等于固定数值0，之后由用户配置并保存。查看详情不提供重置按钮。
- 历史草稿未主动重新配置时原样保留；已发布任务和归档继续使用冻结定义及证据，不改写历史核算结果。
- 兼容执行器继续识别原运算 AST，按字段值、时间函数、加减、比较、AND/OR顺序执行并记录原值与结果，仅用于读取已有定义。

## 数据输入拆分

| 字段 | 口径 |
| --- | --- |
| 总保费 | 有效运营统计中的总成交金额 |
| 早班保费 | [06:00,08:00)实际小时成交贡献合计 |
| 正常保费 | 总保费−夜班保费−早班保费（2026-10-16确认） |
| 正常直播时长 | 总直播时长−夜班直播时长−早班直播时长 |
| 早班/夜班场次 | 沿用连续同团队合并场次规则 |

月度含nightPremium、earlyPremium、regularPremium、regularHours、regularSpend及spendRank。夜班和早班保费为可核验修正的基础值，二者之和不得超过总保费；运营表中的正常保费、正常消耗和正常时长自动计算，不接受人工填写。薪酬核算结果表属于独立复核层，允许直接修正其数值，不自动重算其他结果字段，也不回写运营表。时报/日报来源、人工纠正与下游分配延续既有审计；缺少夜班或早班金额的旧历史仍为未知，不按时长比例猜作实际平台金额。

## 三阶段规则及合并

### 1 补贴

选择员工月度汇总中的计数指标，当前可选夜班场次、早班场次、等待薪资天数，设置每次（或每天）补贴金额。每条命中规则金额=所选计数指标×补贴金额，同一行所有补贴金额累加。计数必须为非负整数，金额必须为有限非负数。等待薪资天数由运营人工维护，未填写不按0核算；可用于统计指标档位及数值条件，但不属于以小时计的计薪时长字段。补贴不改变保费、消耗和时长，也不再参与后续系数相乘。

### 2 保费系数

名称统一为“保费系数规则”。规则包含一个或多个可新增、删除的系数项，每项配置名称、保费字段和保费系数。字段可选总保费、夜班保费、早班保费、正常保费，系数为有限非负数，允许0和小于1的折减。只读公式随项目列表自动生成“系数项1 + 系数项2 + …”，单项金额=原始保费字段×该项系数。

多个范围的保费系数规则同时命中时，每条规则独立读取同一份原始月度数据，先求本规则所有系数项总额，再取最高总额作为有效总保费；不逐字段拼出新规则，不叠加规则结果，也不与原始总保费再次取最大。未命中任何保费系数规则才沿用原始总保费。未选字段不自动补入；默认“正常保费×1 + 早班保费×1.2”仍排除夜班，只有显式加入夜班或总保费项才计入对应金额。正常保费始终=总保费−夜班保费−早班保费。

例如原始正常保费700、早班200、夜班100，规则A=正常×1+早班×2=1100，规则B=总保费×1.05=1050，采用A的1100，而不是选择数值最大的单个系数后重新套用其他字段。零系数结果有效。

计算使用工作副本，不回写运营数据；有效总保费、有效ROI及同直播间同月ROI排名随选中结果更新，后续时薪使用有效值。原始组成字段的取值依据保留在计算轨迹中。保费不直接作为工资金额相加。轨迹包含各候选规则、逐项原值、系数、金额、总额及是否采用，便于复核；结算层的有效字段与范围金额口径见[分层核算规格](2026-10-16-layered-payroll-settlement.md)。

### 3 时薪

每条时薪规则先选择总/夜班/早班/正常直播时长之一，再单选一种时薪计算类型；同一条规则不混合三种类型，切换类型清除当前未保存的类型配置。

- 统计指标加成：以列表管理指标，支持新增、编辑、删除；配置弹窗包含名称、统计指标和时薪档位，匹配方式支持精确数值、数值范围和关联指标范围。精确数值用于当前指标等于指定值的情况，例如有效 ROI 排名第1名 → 80元/小时、第2名 → 60元/小时；数值范围支持开放上下界。只读计算公式按列表顺序显示全部指标名称之和，增删、改名时自动更新，不再手动选择公式项目。

  档位列表底部提供“新增档位”，无须返回顶部。已有档位默认以一行展示序号、匹配条件、时薪和编辑/删除操作；开闭区间及关联指标均在摘要中明确表达。精确数值档位在查看、编辑及保存时均保留精确匹配类型，不再自动转换为闭区间；已有闭区间仍保留原类型。精确模式仅填写数值及时薪，范围模式填写上下限及边界；切换匹配方式会清除不适用的数值、范围和关联字段。重复精确值、精确值落入同指标其他范围时均按重叠拒绝保存；运行时仍须唯一命中。有效 ROI 排名沿用同直播间同月的竞争排名，并列第1名均匹配数值1，下一名匹配数值3。取消不保存，历史快照不改写。新增或编辑时仅展开当前档位，点击“完成”通过完整档位校验后收起。切换编辑时仅检查当前档位的字段完整性，允许调整相邻区间时暂时重叠；完成、新增下一档位和保存时检查区间重叠。删除前序档位后仍保持正在编辑的同一条数据。新建统计指标或更换统计指标时，初始档位自动展开。只读详情展示相同摘要，不提供编辑操作。
- 特殊时段加成：直接设置加成金额（元/小时），按本规则选择的时长计薪，不显示指标列表或档位。
- 条件保薪：配置保薪条件与保薪值来源。来源可选固定值（元/小时）或员工月度汇总表中的数值字段，例如“过去3个月的平均时薪”；不显示指标列表或档位。切换来源清除另一种配置，公式和只读摘要展示字段名称。

#### 条件保薪字段来源（2026-10-16）

`HourlyItem` 使用互斥的 `rate` 与 `rateField`：固定时薪保存 `rate: 60`，字段时薪保存 `rateField: "past3MonthsAvgHourlyRate"`，不同时保存两种来源。只有条件保薪可使用字段来源；统计指标加成与特殊时段加成沿用各自配置。

字段下拉复用员工月度汇总表实际数值列，排除日期、文本、布尔和旧辅助字段。读取同员工、同直播间、同年月的原始月度汇总值；若选择总保费、ROI、ROI排名，使用汇总表原值，不使用保费系数处理后的有效值。条件判断、统计指标档位原有的有效指标语义保持不变。

条件命中后读取所选字段作为元/小时值，并乘本规则计薪时长。字段必须是有限非负数，0有效；缺失、负数或非法值阻止该次核算，不能静默替换为0。条件未命中时不读取该保薪字段，也不因其缺失阻断其他规则。核算依据保存字段名、实际取值、时薪及时长，统计原值和规则版本随批次冻结。

员工月度汇总新增“过去3个月的平均时薪”，接口名 `past3MonthsAvgHourlyRate`，单位元/小时、常规指标、可空非负小数。DEMO 沿用月度编辑与修订审计维护此值，刷新保留人工值，归档后只读。历史平均计算口径尚未定义，本次不自动读取归档薪资推算，也不将过去4个月等窗口做成规则变量；已有记录缺失时显示“未定义”。MySQL 建议使用 `past_3_months_avg_hourly_rate DECIMAL(18,6) NULL DEFAULT NULL` 并约束非负。

示例：选择“入职日期，在过去3个月内”，核算月2026年10月，入职日期2026年8月1日，条件命中。选择本行“过去3个月的平均时薪”65.25元/小时、计薪总时长100小时，得到保底金额6525元，无需配置时间函数或加减表达式。

单条统计指标规则公式必须包含全部指标且顺序一致，特殊时段与条件保薪分别只有一份配置。各条规则先以自身时薪乘所选时长得到金额，再合并：保薪金额取最大，加成金额全部累加，最终采用两者较高金额。不同直播间分别处理，不跨直播间平均ROI。此处金额层比较替代早期“各时长组分别取高再相加”的口径。

例如同一时长下保薪60、加成80，等价采用80元/小时；若总时长保薪50×100小时=5000、夜班保薪200×20小时=4000，最终保底为5000，不按时薪200选取4000，也不把两项保底相加。

### 月薪

总计绩效金额=max(最大保底金额,累计加成金额)，行月薪=总计绩效金额+总补贴；员工月薪为该员工各直播间行月薪之和，即该员工绩效合计与补贴合计之和。结果指标在“总计月薪”前列示“总计绩效金额”。例：总保费1000、夜班保费0、早班保费200，两条公式“正常×1＋早班×1.2”和“正常×1＋早班×1.5”分别得到1040和1100，采用1100；夜班2场、两条每场补贴20和10则补贴60；总时长10小时、保薪60得保底600、加成80得加成800；另有夜班2小时×10元加成20，则绩效=max(600,820)=820，月薪=820+60=880。

## 校验与任务

范围及日期、基础数据有限非负、整数字段、总量关系、重复员工直播间月份、规则及项目ID、公式引用、档位缺失/多命中、无效分母及金额溢出均校验。失败不产生部分工资。

保存生成草稿版本；发布仅保存可用规则版本，不选择月份、不依赖数据就绪、不生成任务。直播间规则集以共同版本和完整成员原子发布，草稿编辑/删除成员不改变先前发布版本，直到重新发布完整组或删除规则集。每月1日00:00（Asia/Shanghai）自动生成上月唯一待核算任务，缺规则或数据时仍生成。HR在详情二次确认核算时读取最新已发布规则及确认月度数据，再冻结月份、月末基准、员工名单、行键和数据版本。成功后保存两张结果表并进入待复核，不自动归档。核算后发布版本或数据变化必须重新核算，草稿变化不影响已核算结果。HR在人工修正已应用且依据仍有效时手动归档，详细调度、幂等及存储见[月度任务与复核规格](2026-10-16-payroll-review-workflow.md)。

新旧规则任务分离，旧部门规则及其工资保留原引擎与快照。新旧有效待核算任务混合时拒绝，先撤回旧任务再使用新版，不能把两套模型的结果盲目相加。

### 删除规则

全局规则和直播间规则集提供确认删除入口，以deletedAt逻辑删除当前定义并从可用发布版本移除，释放当前直播间占用。月度自动任务继续保留；未归档计算结果提示重新核算，已归档结果及冻结规则不变。旧历史待核算输入继续按原规则原子撤回，归档月异常待输入拒绝变更。已删除规则不能继续保存或发布。

## 持久化与审计

DEMO以compensationRules保存当前草稿/定义、publishedCompensationRules独立保存可用发布快照，roomRuleSetId表达分组。monthlyPayrollJobs按月份保存调度任务；compensationTasks在HR核算时保存完整输入证据与组成员元数据，批次标记ruleSource=published-rules。新增字段缺省为空；旧发布版本从当前已发布定义或同范围历史输入迁移，旧任务与归档原样保留。沿用现有持久化命名空间和版本1；初始样例仅为草稿，不自动发布。

正式MySQL新增`compensation_rule_sets`保存直播间规则集ID、版本、状态、并发版本和deleted_at，`compensation_rule_set_rooms`保存当前绑定（room_id唯一、rule_set_id外键）。`compensation_rules.rule_set_id`可空，直播间成员必填，全局为空；有效成员的(rule_set_id, calculation_type)唯一，使用可空的有效类型生成列确保逻辑删除后可重新添加同类规则。保存时在事务内锁定规则集及直播间绑定，统一验证1至3条有效成员及类型唯一、更新版本和绑定。版本表冻结完整成员定义及范围，核算快照保存规则集ID/版本/完整成员ID；发布和删除整组原子提交。旧单条直播间规则迁移为单成员组，旧冻结任务不回写。除旧员工规则迁移为全局草稿外，规则分类创建后不可更改。拟增加compensation_rules及rule_versions（global/rooms范围、计算类型、definition_version、模板配置、版本及deleted_at；条件AST仅用于条件保薪或历史兼容）、payroll_monthly_jobs（每月1日生成上月任务、月份唯一）及payroll_run_rule_snapshots/payroll_run_input_snapshots（HR核算时保存日期基准、冻结规则、员工名单、行键及统计版本）、payroll_row_calculations（命中规则、候选保费公式与采用结果、有效ROI/排名、保薪/加成、时长、补贴及结果）。删除规则、移除可用发布版本、释放当前绑定必须原子提交，月度自动任务不删除；冻结版本不被删除。模板JSON记录补贴计数字段、系数项数组、时薪子类型及指标项。JSON条件必须通过服务端相同类型校验，不能作为SQL/脚本执行。

原始核算快照冻结上述计算依据、当期员工协议/入职值、直播间开播日期和规则版本。HR归档还冻结已应用的最终明细、员工汇总、自定义列及复核审计。以后修改员工、直播间或草稿均不改历史工资。六条原始来源规则只读保留，未作不等价自动转换。

新建规则使用`definitionVersion=2`。旧员工范围迁移只修改当前规则分类与条件，不擅自改写计算配置；其他旧模板数据及所有冻结任务不自动改写；查看显示原配置，编辑时生成新模板草稿并提示差异：旧保费规则转换为正常与早班系数项，原系数触发条件不带入；旧时薪公式按第一个有效项目确定类型，仅保留相同类型（特殊时段/保薪保留一项），旧加成触发条件不带入。取消不保存这些变化，保存后才生成新草稿版本。旧任务继续引用原快照。

## 页面

规则页从全局、直播间两个水平分类开始。全局分类显示“新增薪酬规则”，直播间分类显示“新增直播间规则集”，再展示相应列表；新增默认归属当前分类。移除页面标题说明、核算月份选择、规则数量概览、计算顺序提示及“来源与历史规则”入口。单规则卡片保留名称、类型、版本、状态、计算摘要和操作。规则集卡片展示共享直播间、组版本/状态及成员摘要，提供查看详情、编辑、删除与整组发布。

弹窗顶部只读展示分类。全局无员工筛选条件；直播间先选择范围，再用统一组件选择计算类型、维护名称与配置。发布弹窗只确认名称、版本、类型、适用范围和配置摘要，不选择核算月份或数据版本。条件保薪的 AND/OR、日期、布尔和数字配置继续可用。

薪酬核算列表仅保留任务筛选栏和按月份合并的只读任务摘要（含状态），不提供列表级“开始月度核算”或独立月份操作区。点击在当前页进入详情，支持返回并保留筛选；核算及重新核算须二次弹框确认。

详情提供基础信息及“月度核算明细”“员工月薪汇总”两个可检索、导出结果页签。明细支持追加文本/数字/金额表头与直接编辑数值结果；关联标识只读，编辑不自动重算其他字段。修改后显式执行“应用”，按员工汇总明细的总计月薪更新只读员工月薪汇总；追加字段不自动参与工资。记录修改理由、操作人、前后值和版本。待应用修正禁止归档。

具备归档权限的 HR 复核无误后二次确认归档；管理员演示身份可执行。来源、确认月度数据或已发布规则在核算后变化必须重新核算，归档冻结最终两表、追加列、审计及来源，并更新全局归档月份。历史三分类结果按原快照只读展示，不按新范围重算。
