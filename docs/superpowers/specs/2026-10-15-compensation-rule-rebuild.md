# 薪酬规则重构规格

日期：2026-10-15；更新于2026-10-16。本文件记录全局、直播间两分类及补贴、保费系数、时薪三类型规则的配置规格。核算复核与手动归档以[月度任务与复核规格](2026-10-16-payroll-review-workflow.md)为准。

## 员工与直播间字段

员工增加`non_compete_signed BOOLEAN NOT NULL DEFAULT FALSE`，前端`nonCompeteSigned`。新增及历史缺省员工补False，保存只接受布尔值；档案与本人资料显示签约状态。旧归档人员快照不回写。

直播间增加可维护的`opened_on DATE NULL`开播日期，用于开播月龄条件；不把最早采集日期猜作真实开播日。规则引用缺失的开播/入职日期时提示补齐，不自动当作命中或不命中。

## 范围分类

| 分类 | 定义方式 |
| --- | --- |
| 全局规则 | 直接定义，无员工筛选条件，适用于全部符合结算资格的在职主播月度行 |
| 直播间规则 | 下拉多选未被其他当前规则集占用的直播间，再添加规则集；补贴、时薪、保费系数每类至多一条 |

分类由新增入口确定，新增、编辑和详情中的分类字段均只读，保存接口拒绝已有规则切换分类。全局规则直接进入定义，直播间规则先配置适用直播间；两类共用同一规则定义组件，依次选择计算类型、定义规则名称及对应配置（保费系数、时薪的保薪/加成、补贴）。全局分类维护单条规则，直播间分类维护规则集。

取消独立员工规则分类及员工范围条件。旧当前员工规则保留名称和计算配置，迁移为全局草稿、版本递增并移除 `employeeCondition`；适用范围扩大后必须重新发布。历史已发布任务和归档快照保留原分类与条件，不改写历史金额。条件保薪内部的员工条件仍可配置，不因范围条件取消而删除。

直播间下拉框支持多选，一个直播间只能归属一个未删除规则集，草稿和已发布均占用。集内补贴、时薪、保费系数共享相同直播间范围，每类至多一条，可只配置其中一类或两类。其他规则集已选的直播间显示占用并禁选；编辑排除整个当前规则集。全局规则不占用直播间。保存、发布校验当前绑定唯一性；历史归档快照不占用当前绑定。同月其他规则集的待核算快照仍包含该直播间时，必须先撤回相关任务再发布。

规则集编辑先选直播间，再选未使用的计算类型添加规则，随后填写名称与配置。子规则类型在本次配置中只读，需要更换类型时删除后重新添加。未编辑的子规则仅展示类型、名称和计算摘要；新增或编辑时仅展开一条，完成后收起。可删除集内子规则，保存时至少保留一条。规则集统一保存、发布、删除；不提供单独发布子规则的入口。已有直播间单条规则显示为单条规则集，首次保存才写入分组标识，不改历史任务。

范围分类与计算类型独立。每条员工＋直播间＋月份数据行先匹配全部已发布有效规则，再合并成一套结果计算一次；不把每条时薪规则独立算薪后重复相加。

## 条件与日期

使用类型受控的字段、运算符、值与嵌套AND/OR组，不执行自由JavaScript。规则范围不再配置员工条件；条件保薪仍可引用员工、直播间和月度指标。新保费系数规则直接配置系数项，不再配置早班场次触发条件。

以核算月份最后一天为判断基准并冻结。布尔和文本只支持等于/不等于；数值支持比较。空组、未知字段、错误值类型和循环/过深结构拒绝。必要输入缺失不猜测。

### 日期字段与时间函数（2026-10-16）

保薪条件按“字段 → 时间函数 → 比较符 → 对比字段”配置。日期字段的时间函数提供“不处理（日期）”“提取年份”“提取月份”，不开放自由函数或脚本。

| 左侧处理 | 结果类型 | 右侧可选范围 | 示例 |
|---|---|---|---|
| 不处理 | 日期 | 日期字段 | 入职日期 ≤ 直播间开播日期；入职日期 ≤ 核算基准日（月末） |
| 提取年份 | 数值 | 数值型字段 | 提取年份（入职日期）= 汇总年份 |
| 提取月份 | 数值 | 数值型字段 | 提取月份（入职日期）= 汇总月份 |

- 日期字段包含入职日期、直播间开播日期和核算基准日（月末）；基准日随任务冻结，不使用浏览器当前日期。
- 新增数值条件字段“汇总年份”“汇总月份”。年份读取员工月度汇总的年份，月份将该行的 `YYYY-MM` 期间映射为 1–12 的整数，不把整段期间字符串作为数字比较。
- 右侧列表由左侧处理后的类型过滤；切换字段或时间函数时清理不再合法的比较目标。日期字段不处理时禁止选择数值字段；提取年份或月份后禁止选择日期字段。比较符支持等于、不等于、大于、大于等于、小于、小于等于。
- 新建日期条件采用字段比较，不再显示固定值输入框。其他数值、文本、布尔字段的既有固定值条件不变。
- 判断“入职当月”需同时配置年份相等与月份相等，并使用 AND。仅比较月份表示跨年份的同一月份，这是使用者明确选择的条件，不隐式增加年份限制。
- 日期以 `YYYY-MM-DD` 的日历日期处理，提取年、月不会受浏览器时区影响。非法日历日期、缺失日期、非法数值或未知函数必须报错，不允许自动转换或默认为不命中。AND/OR 所有分支都校验必要输入。
- 历史固定日期与“最近 N 个月内”条件保留原定义及结果；查看和原样保存不改写，编辑器明确标为已有条件。选择新的时间函数或字段比较后按本节类型规则配置。旧“最近 N 个月内”继续采用含下限、含基准日的日历月回溯，月末夹至目标月末且排除未来日期。

条件 AST 使用 `field` 表示左字段、可选 `transform: "year" | "month"` 表示时间函数、`compareField` 表示右字段；字段比较不同时保存 `value`。例如当月入职条件为：

```json
{"kind":"group","operator":"and","children":[
  {"kind":"condition","field":"employee.joined","transform":"year","operator":"eq","compareField":"monthly.year"},
  {"kind":"condition","field":"employee.joined","transform":"month","operator":"eq","compareField":"monthly.month"}
]}
```

MySQL 的规则版本 JSON 保存完整 AST；发布任务冻结 AST、核算基准日及来源版本，核算证据记录左右字段原值及时间函数结果。服务端执行相同类型白名单校验。归档后仍读取冻结结果，不因员工资料或当前规则改变而重新解释历史条件。

## 数据输入拆分

| 字段 | 口径 |
| --- | --- |
| 总保费 | 有效运营统计中的总成交金额 |
| 早班保费 | [06:00,08:00)实际小时成交贡献合计 |
| 正常保费 | 总保费−夜班保费−早班保费（2026-10-16确认） |
| 正常直播时长 | 总直播时长−夜班直播时长−早班直播时长 |
| 早班/夜班场次 | 沿用连续同团队合并场次规则 |

月度含nightPremium、earlyPremium、regularPremium、regularHours、regularSpend及spendRank。夜班和早班保费为可核验修正的基础值，二者之和不得超过总保费；运营表中的正常保费、正常消耗和正常时长自动计算，不接受人工填写。薪酬核算结果表属于独立复核层，允许直接修正其数值，不自动重算其他结果字段，也不回写运营表。时报/日报来源、人工纠正与下游分配延续既有审计；缺少夜班或早班金额的旧历史仍为未知，不按时长比例猜作实际平台金额。

## 三阶段规则及合并

### 1 补贴

选择员工月度汇总中的计数指标，当前可选夜班场次、早班场次、等待薪资天数，设置每次（或每天）补贴金额。每条命中规则金额=所选计数指标×补贴金额，同一行所有补贴金额累加。计数必须为非负整数，金额必须为有限非负数。等待薪资天数由运营人工维护，未填写不按0核算；可用于统计指标档位及数值条件，但不属于以小时计的计薪时长字段。补贴不改变保费、消耗和时长，也不再参与后续系数相乘。

### 2 保费系数

名称统一为“保费系数规则”。规则包含一个或多个可新增、删除的系数项，每项配置名称、保费字段和保费系数。字段可选总保费、夜班保费、早班保费、正常保费，系数为有限非负数，允许0和小于1的折减。只读公式随项目列表自动生成“系数项1 + 系数项2 + …”，单项金额=原始保费字段×该项系数。

多个范围的保费系数规则同时命中时，每条规则独立读取同一份原始月度数据，先求本规则所有系数项总额，再取最高总额作为有效总保费；不逐字段拼出新规则，不叠加规则结果，也不与原始总保费再次取最大。未命中任何保费系数规则才沿用原始总保费。未选字段不自动补入；默认“正常保费×1 + 早班保费×1.2”仍排除夜班，只有显式加入夜班或总保费项才计入对应金额。正常保费始终=总保费−夜班保费−早班保费。

例如原始正常保费700、早班200、夜班100，规则A=正常×1+早班×2=1100，规则B=总保费×1.05=1050，采用A的1100，而不是选择数值最大的单个系数后重新套用其他字段。零系数结果有效。

计算使用工作副本，不回写运营数据；有效总保费、有效ROI及同直播间同月ROI排名随选中结果更新，后续时薪使用有效值。原始组成字段的取值依据保留在计算轨迹中。保费不直接作为工资金额相加。轨迹包含各候选规则、逐项原值、系数、金额、总额及是否采用，便于复核；结算层的有效字段与范围金额口径见[分层核算规格](2026-10-16-layered-payroll-settlement.md)。

### 3 时薪

每条时薪规则先选择总/夜班/早班/正常直播时长之一，再单选一种时薪计算类型；同一条规则不混合三种类型，切换类型清除当前未保存的类型配置。

- 统计指标加成：以列表管理指标，支持新增、编辑、删除；配置弹窗包含名称、统计指标和时薪档位，匹配方式仅提供数值范围和关联指标范围，支持开放上下界，不再提供精确数值。只读计算公式按列表顺序显示全部指标名称之和，增删、改名时自动更新，不再手动选择公式项目。

  档位列表底部提供“新增档位”，无须返回顶部。已有档位默认以一行展示序号、匹配条件、时薪和编辑/删除操作；开闭区间及关联指标均在摘要中明确表达。历史精确数值档位在查看时保留原摘要，进入编辑时等价转换为上下限相同且均包含边界的闭区间；取消不保存，历史快照不改写。新增或编辑时仅展开当前档位，点击“完成”通过完整档位校验后收起。切换编辑时仅检查当前档位的字段完整性，允许调整相邻区间时暂时重叠；完成、新增下一档位和保存时检查区间重叠。删除前序档位后仍保持正在编辑的同一条数据。新建统计指标或更换统计指标时，初始档位自动展开。只读详情展示相同摘要，不提供编辑操作。
- 特殊时段加成：直接设置加成金额（元/小时），按本规则选择的时长计薪，不显示指标列表或档位。
- 条件保薪：直接配置保薪条件与保薪值（元/小时），例如开播未满3个月或新人主播，不显示指标列表或档位。

单条统计指标规则公式必须包含全部指标且顺序一致，特殊时段与条件保薪分别只有一份配置。各条规则先以自身时薪乘所选时长得到金额，再合并：保薪金额取最大，加成金额全部累加，最终采用两者较高金额。不同直播间分别处理，不跨直播间平均ROI。此处金额层比较替代早期“各时长组分别取高再相加”的口径。

例如同一时长下保薪60、加成80，等价采用80元/小时；若总时长保薪50×100小时=5000、夜班保薪200×20小时=4000，最终保底为5000，不按时薪200选取4000，也不把两项保底相加。

### 月薪

行月薪=max(最大保底金额,累计加成金额)+总补贴；员工月薪为该员工各直播间行月薪之和。例：总保费1000、夜班保费0、早班保费200，两条公式“正常×1＋早班×1.2”和“正常×1＋早班×1.5”分别得到1040和1100，采用1100；夜班2场、两条每场补贴20和10则补贴60；总时长10小时、保薪60得保底600、加成80得加成800；另有夜班2小时×10元加成20，则max(600,820)+60=880。

## 校验与任务

范围及日期、基础数据有限非负、整数字段、总量关系、重复员工直播间月份、规则及项目ID、公式引用、档位缺失/多命中、无效分母及金额溢出均校验。失败不产生部分工资。

保存生成草稿版本，发布冻结规则、月份、月末基准、员工名单、数据行键与数据集版本。直播间规则集所有成员以共同版本原子保存和发布，每个成员生成一份底层规则发布输入，同时冻结规则集ID、成员ID和版本；整组成功才提交。撤回任一成员发布输入会撤回该规则集同月全部待核算输入。核算拒绝缺失成员或混用组版本。删除成员时撤回该组全部待核算任务；重新发布使用新的完整成员集合。发布后修改来源/统计版本或适用行范围，核算拒绝，撤回待任务并核对后重新发布。同月已发布规则输入聚合为一条月度核算任务，整月调用合并引擎一次。用户在任务详情二次确认后执行核算，成功后保存两张结果表并进入待复核，不自动归档；HR 在人工修正已应用、来源及任务版本仍有效时手动确认归档。

新旧规则任务分离，旧部门规则及其工资保留原引擎与快照。新旧有效待核算任务混合时拒绝，先撤回旧任务再使用新版，不能把两套模型的结果盲目相加。

### 删除规则

全局规则卡片提供删除入口；直播间规则集卡片删除整个规则集及其成员，确认弹窗显示规则名称和待撤回任务数量。确认后以`deletedAt`标记删除，从当前列表移除并释放直播间占用，同一事务撤回该规则全部月份的待核算任务。已核算任务、历史工资、归档及其规则快照保持原样。已删除规则不能继续保存或发布，防止旧编辑窗口恢复规则。若相关待核算任务属于归档月份，拒绝整个删除操作，避免部分删除或篡改归档。

## 持久化与审计

DEMO继续以平铺的compensationRules保存各子规则，新增可选roomRuleSetId表达直播间分组；无分组ID的旧直播间规则按自身ID作为单条规则集。compensationTasks冻结组成员元数据；核算仍读取各类型规则，不改变合并算法。新增compensationRules/compensationTasks及一次初始化标记，沿用现有存储命名空间和版本1；不清空员工、来源、工资或归档。初始化仅提供明确标识的草稿样例，不自动发布。

正式MySQL新增`compensation_rule_sets`保存直播间规则集ID、版本、状态、并发版本和deleted_at，`compensation_rule_set_rooms`保存当前绑定（room_id唯一、rule_set_id外键）。`compensation_rules.rule_set_id`可空，直播间成员必填，全局为空；有效成员的(rule_set_id, calculation_type)唯一，使用可空的有效类型生成列确保逻辑删除后可重新添加同类规则。保存时在事务内锁定规则集及直播间绑定，统一验证1至3条有效成员及类型唯一、更新版本和绑定。版本表冻结完整成员定义及范围，任务保存规则集ID/版本/完整成员ID；发布、撤回和删除整组原子提交。旧单条直播间规则迁移为单成员组，旧冻结任务不回写。除旧员工规则迁移为全局草稿外，规则分类创建后不可更改。拟增加compensation_rules及rule_versions（global/rooms范围、计算类型、definition_version、模板配置、版本及deleted_at；条件AST仅用于条件保薪或历史兼容）、compensation_tasks（日期基准、冻结规则、员工名单、行键及统计版本）、payroll_row_calculations（命中规则、候选保费公式与采用结果、有效ROI/排名、保薪/加成、时长、补贴及结果）。删除规则、释放当前绑定、撤回待任务必须原子提交；冻结版本不被删除。模板JSON记录补贴计数字段、系数项数组、时薪子类型及指标项。JSON条件必须通过服务端相同类型校验，不能作为SQL/脚本执行。

原始核算快照冻结上述计算依据、当期员工协议/入职值、直播间开播日期和规则版本。HR归档还冻结已应用的最终明细、员工汇总、自定义列及复核审计。以后修改员工、直播间或草稿均不改历史工资。六条原始来源规则只读保留，未作不等价自动转换。

新建规则使用`definitionVersion=2`。旧员工范围迁移只修改当前规则分类与条件，不擅自改写计算配置；其他旧模板数据及所有冻结任务不自动改写；查看显示原配置，编辑时生成新模板草稿并提示差异：旧保费规则转换为正常与早班系数项，原系数触发条件不带入；旧时薪公式按第一个有效项目确定类型，仅保留相同类型（特殊时段/保薪保留一项），旧加成触发条件不带入。取消不保存这些变化，保存后才生成新草稿版本。旧任务继续引用原快照。

## 页面

规则页从全局、直播间两个水平分类开始。全局分类显示“新增薪酬规则”，直播间分类显示“新增直播间规则集”，再展示相应列表；新增默认归属当前分类。移除页面标题说明、核算月份选择、规则数量概览、计算顺序提示及“来源与历史规则”入口。单规则卡片保留名称、类型、版本、状态、计算摘要和操作。规则集卡片展示共享直播间、组版本/状态及成员摘要，提供查看详情、编辑、删除与整组发布。

弹窗顶部只读展示分类。全局无员工筛选条件；直播间先选择范围，再用统一组件选择计算类型、维护名称与配置。核算月份仅在发布弹窗中选择。条件保薪的 AND/OR、日期、布尔和数字配置继续可用。

薪酬核算列表仅保留任务筛选栏和按月份合并的只读任务摘要（含状态），不提供列表级“开始月度核算”或独立月份操作区。点击在当前页进入详情，支持返回并保留筛选；核算及重新核算须二次弹框确认。

详情提供基础信息及“月度核算明细”“员工月薪汇总”两个可检索、导出结果页签。明细支持追加文本/数字/金额表头与直接编辑数值结果；关联标识只读，编辑不自动重算其他字段。修改后显式执行“应用”，按员工汇总明细的总计月薪更新只读员工月薪汇总；追加字段不自动参与工资。记录修改理由、操作人、前后值和版本。待应用修正禁止归档。

具备归档权限的 HR 复核无误后二次确认归档；管理员演示身份可执行。来源或输入任务在核算后变化必须重新核算，归档冻结最终两表、追加列、审计及来源，并更新全局归档月份。历史三分类结果按原快照只读展示，不按新范围重算。
