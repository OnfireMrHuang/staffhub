# 投放产品与直播间 DEMO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 运营关系拆成投放产品和直播间，关联表及规则同步；头部归档状态只读，清空现有核算数据。

**Architecture:** 产品维护平台、投放账户与应用凭据；直播间维护直播账户并引用一个产品。直播记录及工资按直播间关联，统计中展示产品与直播间两组字段。本次数据升级仅清空核算任务、工资和归档，保留人员、来源、运营统计及规则配置。

**Tech Stack:** React、Vite、Radix UI、Zustand、TypeScript、Vitest。

**Spec:** 主规格及2026-10-14用户要求；已确认每直播间一个直播账户，投放取数粒度为产品＋直播间＋小时。

## Global Constraints
- 员工基础数据不变，姓名唯一及日期、整小时、归档保护继续有效。
- 头部只读展示最近薪酬归档月份，无归档显示“暂无归档”，不作为业务月份选择器。
- 产品字段：产品ID/名称、关联平台、投放账户ID、状态、应用ID/密钥/授权码；密钥和授权码只持久化是否配置。
- 直播间字段：直播间ID/名称、平台账户ID、状态、关联产品；不维护员工关系。
- 数据录入、模板、上传校验、预览、导出、表结构及数据集展示一致的产品/直播间关系，规则绑定直播间。
- 不提交、不外部发布；保存旧资料，禁止因模型改名静默重复累加金额。

## Review Focus
- 同产品多直播间时投放基础数据不重复统计。
- 模板四个关联字段必须彼此一致，上传不可通过伪造产品名绕过。
- 已有来源后账号及归属不能改写历史；名称变化不改变稳定ID。
- 清空工资数据不清空员工、来源或规则；重载不会每次反复清除新任务。
- 业务月份选择迁至业务页，归档月份不能手动输入。
