# 时报、日报与统一月度汇总实现记录

## 接口与固定定义

- `src/pages/RoomReports.tsx` 默认导出接受 `{period:'hourly'|'daily'}`；`LiveDatasets` 现在只有全局员工月度表。
- `src/room-reports.ts` 提供可检查的纯报表模型、字段元数据、DEMO固定绑定、小时来源归一化与分层修订。
- `demo-performance` 为成交效率样例，两个初始直播间共用定义；`demo-audience` 为直播互动样例。后者实际包含观看人次、粉丝、打赏次数，前者包含点击、转化及成本，结构不只是名称不同。UI明确标记样例，实际表头、公式和绑定待后台提供。
- 新建或既有自定义直播间无定义时不套用通用表头；报表页显示未绑定且不可编辑。为了不改变旧数据及工资，这些直播间仍可使用原始统计兼容来源进入月度；月度页列出具体直播间和该边界。该兼容来源在内部同样归一化为小时及团队贡献，不声称存在已定义的时报/日报。

## 粒度、来源与汇总

- 时报只取已匹配直播记录的真实整一小时平台来源；不把两小时记录平均拆成小时测量。
- 日报粒度为直播间、日期、主播/投手/场控三岗组合。间隔不算时长；金额及数量相加，比率重算；单一小时缺可选分母时保留平台原始率，修改对应分子后显示未定义，多小时缺完整分母时不平均平台率。
- 月度始终从有效报表贡献按员工、直播间、年月汇总；兼岗只贡献一次。保留原来夜班、早班和连续场次规则，跨月场次保留上下文。
- 归一小时贡献带 `LiveDetail.sourceRecordId`。汇总时用归一小时替换其原直播段的场次上下文，防止原段与小时交错造成重复场次。
- 时报修订进入日报；日报人工覆盖在其后应用。日报金额按照原贡献比例分配到下游班次依据，仅供月度计算，不回写或冒充小时测量。内部其他日基础值同样以贡献分配，月度薪酬只读取其原来支持的金额、时长、场次等指标；时报与日报公开计数编辑仍要求整数。
- 日报覆盖只保存可编辑基础值和岗位关联的权威性，实际时长、来源清单、分母等只读元数据始终读取最新上游。
- 独立月度覆盖最后应用，具有最终权威性；不会因时报或日报刷新重复加成或消失。

## 历史覆盖、持久化与归档

- 旧 `detailOverrides` 保持整段身份、原月份、修订历史及有效贡献。受影响时报仍显示真实小时来源，并显著标识历史整段覆盖；先恢复旧覆盖后才能编辑关联时报，禁止猜分整段修订数值。
- 旧修订跟踪区可从原直播间或移动后的直播间查看和恢复；日报和月度继续采用旧整段有效贡献。
- 新状态为 `reportHours`、`reportDays`、`reportOverrides`、`reportAudit`。新数组在旧持久化状态中默认为空；持久化key与version1均未改变。
- 原始记录若已参与时报或日报人工覆盖，改变其产品、直播间、日期、三岗或时段前必须先恢复关联修订；输入前原子拒绝，避免失去可恢复的有效快照。未涉及覆盖的其他新增记录仍可正常输入后同步来源。
- 新保存/恢复均要求原因、当前有效统计版本和未归档月份。候选汇总完成且无关联冲突后才单次写入；未通过验证不写审计、不增版本。
- 新工资归档包含有效时报、日报、实际月度贡献、字段定义与版本、直播间绑定、人工覆盖和审计；读取归档时不查询当前定义或重算。
- 旧归档缺少报表快照时，显示“该归档无时报 / 日报快照”，不补算；既有月度与工资完全沿用原冻结依据。

## 验证

- 先运行缺失模型/缺失store字段的失败测试，再实现；对打赏计数语义、日报覆盖错误冻结时长、快照缺少贡献分别先复现失败后修复。

- `npm run build`：通过。Vite保留现有体积警告，主bundle略超500KB。
- 本实现任务未运行服务、未操作浏览器、未修改持久化数据，浏览器验收由父任务执行。
