# 运营数据集人工纠正 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 两张运营统计表支持关联字段与基础指标人工纠正，计算指标自动重算，薪酬使用有效修订数据。

**Architecture:** 原始来源保留，人工修改保存独立的完整行覆盖层及审计记录。有效数据按“自动明细→明细覆盖→重建月度汇总→月度覆盖→自动比值与排名”生成。覆盖可恢复自动，刷新不丢失；原月份及目标月份均检查归档，数据集版本用于并发编辑校验。

**Tech Stack:** React、Vite、Radix UI、Zustand、TypeScript、Vitest。

**Spec:** 本轮用户明确允许关联字段编辑，ROI/时耗/排名自动重算。

## Global Constraints
- 两表字段结构固定；编辑的是行数据。ID/名称以现有目录关联选择，名称自动带出。
- 归档月份保持冻结，原月份或目标月份归档则拒绝；不更改员工基础档案及原始录入来源。
- 每次保存必填原因、记录前后值、操作人及时间；覆盖与工资快照持久化，刷新保留人工结果。
- 不改现有薪酬任务快照；名单变化按既有规则阻断，需要撤回任务后重新发布。
- 计算指标只读；无有效分母显示未定义，不能假设为0；有效ROI按直播间同月竞争排名。

## Review Focus
- 明细纠正三岗、日期或直播间后，旧归属移除且新归属只计一次。
- 月度移动关联键不能撞上另一员工＋直播间＋月份行；跨月要同时保护原和目标归档。
- 月度部门按有效统计行作为计薪部门，不直接使用员工当前部门覆盖人工当期归属。
- 刷新、月份切换及重载保留人工修正；恢复自动不删除审计。
- 陈旧弹窗版本不得覆盖新修正，失败不得部分写入。

## Rulings
- 当关联日期或部门手动改变时，统计按修正后的期间和归属计算，不改变基础员工任职。
- 明细消耗修正采用明确班次分配策略，月度班次金额可独立人工纠正。
- 新覆盖字段以默认空数组向后兼容，保留当前持久化版本1，不触发之前清空工资迁移。
- 人工关联移动携带完整修正行，不重读目标日期或直播间小时金额；无原始记录的目标月份允许人工覆盖，仍追溯原来源。已有原始记录缺小时来源会阻断自动基线及修正。
