# 主播分层薪酬固定示例

更新日期：2026-10-17。本示例使用虚构数据，月份为 2026-10。输入在 `src/payroll-settlement-example.ts`，不依赖业务 store；`expected.json` 是独立手算期望，不从引擎输出生成。3 位主播产生 4 行结算结果，1 位纯投手被排除。

带分类表头及可重算公式的[示例工作簿](../../../outputs/layered-payroll-20261016/主播月度薪酬核算示例.xlsx)包含员工月薪汇总、月度核算明细、逐规则计算三个页签。复现脚本为 `outputs/layered-payroll-20261016/build-workbook.mjs`，核验结果见[核验记录](verification.md)。

## 一、规则与范围

当前仅存在全局规则和直播间规则。当前配置中的原员工规则保留计算内容，移除员工筛选条件后迁为全局草稿、版本递增，须重新发布；本例模拟重新发布后的计算。是否签署竞业协议不再决定这些规则的适用范围，历史冻结结果仍保留原分类和筛选依据。

| 范围 | 补贴 | 系数保费候选 | 保底规则 | 加成规则 |
| --- | --- | --- | --- | --- |
| 全局 | 夜班场次×20、早班场次×10、夜班场次×15，求和 | 正常+早班×2（早班场次≥5）；正常+早班×1.5（早班场次≥3）；正常+早班×3（早班场次≥5）；条件不成立系数为1，候选取大 | 总时长×50、夜班时长×200、早班时长×220、总时长×55，金额取大 | 总时长×ROI档位、总时长×排名档位、早班时长×10，金额求和 |
| 直播间 | 0 | 0 | 0 | 正常时长×20，同一规则集绑定一号房与二号房 |

ROI 档位：小于 3 为 20 元/小时，至少 3 为 45 元/小时。排名档位：闭区间 [1,1] 为 10 元/小时，至少 2 为 5 元/小时。本例时薪条件与档位使用系数计算完成后的有效 ROI 和同房主播排名。当前配置另支持条件保薪读取原始月度字段作为时薪；这种字段取值不随有效 ROI 和排名变化，本例未配置该来源。

直播间规则遵守一房一规则集的配置约束，集合内补贴、时薪、保费系数各至多一条；本示例规则集仅含一条时薪规则。旧式条件系数规则仍作为合法引擎输入用于验证兼容计算；这些条件是保费项目的计算条件，不是员工筛选条件。当前 v2 编辑器新建保费规则使用固定系数项目，没有早班场次触发条件；若将此例旧式规则转为 v2，不能认为条件被等价保留。

## 二、林晓·一号房的完整手算

来源：总时长100、夜班20、早班30、正常50小时；夜班10场、早班10场；消耗10,000；原始总保费24,000，其中夜班4,000、早班10,000、正常10,000。

1. 全局保费候选为 10,000 + 10,000×2 = 30,000、10,000 + 10,000×1.5 = 25,000、10,000 + 10,000×3 = 40,000，取 **40,000**。直播间保费类别为0。
2. 两范围取大得到有效保费40,000。有效 ROI=40,000/10,000=**4**；等其他主播也算完后，一号房排名为林晓1、陈雨2、周宁3。
3. 全局补贴=10×20+10×10+10×15=**450**；直播间补贴为0；总计补贴=**450**。
4. 全局保底=max(100×50,20×200,30×220,100×55)=**6,600**；直播间保底为0；最终保底=**6,600**。
5. 全局加成=100×45+100×10+30×10=**5,800**；直播间加成=50×20=**1,000**；累计加成=**6,800**。
6. 行月薪=max(6,600,6,800)+450=**7,250**。有效保费40,000只参与前面的ROI与时薪，不再加到工资。

## 四、示例覆盖点

- 林晓一号房由累计加成6,800决定工资，其他三行由最终保底决定。
- 林晓总时长保底中的50元/小时低于夜班200元/小时，但100×50大于20×200，验证先乘时长再比较金额。
- 林晓一号房从原始ROI 2.4/第3名升至有效ROI 4/第1名，两个时薪档位均改变。
- 未签约的周宁仍参与全部全局规则，证明员工条件已取消。
- 林晓二号房的系数条件都未触发，但仍存在保费候选9,000，不触发「没有系数规则时沿用原始10,000」的回退。
- 直播间规则集同时绑定两房，按每行正常时长分别产生1,000、1,000、600、600，不合并时长。
- 陈雨 `roles=['主播','场控']` 只结算一次。吴策 `roles=['投手']` 不进入工资与主播排名。
- 原始ROI、排名保留在35列统计里；有效ROI与排名只在核算副本和明细中展示。新结果表按“直播数据统计 / 全局核算指标 / 直播间核算指标 / 结果指标”四组展示，列数分别为35、4、4、3，共46列；等待薪资天数作为第34列，人工填写非负整数，样例未提供时显示未定义；过去3个月的平均时薪为第35列，样例未提供时同样显示未定义，可在月度汇总维护后被条件保薪选择；历史员工范围结果保留其范围依据以便追溯。

完整公式、异常、舍入和归档要求见[分层核算规格](../../superpowers/specs/2026-10-16-layered-payroll-settlement.md)。

## 五、月度任务演示

本例2026-10的任务应于2026-11-01 00:00（Asia/Shanghai）生成。发布示例规则只保存可用版本，不创建任务。集成测试模拟该调度日期，随后由HR手动核算并使用当时最新已发布规则和已确认数据，仍得到18,690元。核算后先复核；人工修改明细后明确执行应用，再由HR确认归档。DEMO首次启用只生成当时应核算的上个月任务，不提前创建本例尚未到期的10月任务。
